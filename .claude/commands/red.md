Write a new FAILING test (Red phase of TDD).

1. Read the current plan.md or requirements
2. Write ONE small, focused test that:
   - Tests a single behavior
   - Has a clear, descriptive name (e.g., shouldSumTwoPositiveNumbers)
   - Will fail because the functionality doesn't exist yet
3. Run the test to CONFIRM it fails
4. Report the failing test and its error message

Do NOT:
- Implement any production code
- Write multiple tests
- Write tests that already pass

$ARGUMENTS - Description of the behavior to test
