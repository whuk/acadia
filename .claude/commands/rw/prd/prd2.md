# /rw:prd:prd2 — 상세 설계 문서(PRD2) 생성

프로젝트 루트의 **PRD1.md**를 읽고, 그 위에 상세 설계를 담은 **PRD2.md**를 생성한다.
`$ARGUMENTS`가 있으면 추가 요구사항으로 반영한다.

## 실행 절차

1. 프로젝트 루트의 `PRD1.md`를 Read 도구로 읽는다. 파일이 없으면 사용자에게 `/rw:prd:prd1`을 먼저 실행하도록 안내하고 중단한다.
2. 코드베이스를 탐색하여 현재 구현 상태, 디렉토리 구조, 설정 파일 등을 파악한다.
3. PRD1.md의 내용 + 코드베이스 분석 + `$ARGUMENTS`(추가 요구사항)를 종합하여 PRD2.md를 작성한다.
4. 프로젝트 루트에 `PRD2.md` 파일을 Write 도구로 생성한다.

## PRD2.md 문서 구조

아래 섹션을 **반드시 모두 포함**하여 한글로 작성한다. PRD1.md에서 정의한 기능과 기술스택을 기반으로 일관성을 유지한다.

### 1. 화면별 와이어프레임 / UI 흐름
- 주요 화면 각각에 대해 **ASCII 목업**을 작성한다.
  - 레이아웃, 주요 UI 요소의 위치, 상호작용 포인트를 표현한다.
- **화면 흐름도**: 화면 간 이동 경로를 ASCII 또는 Mermaid 다이어그램으로 표현한다.
- 각 화면의 목적과 핵심 사용자 액션을 설명한다.

### 2. 상세 기능 명세
- PRD1의 대단위 기능 각각에 대해 다음을 기술한다:
  - **프로세스 의사코드**: 핵심 로직을 의사코드로 표현한다. 함수 시그니처, 주요 분기, 데이터 흐름을 포함한다.
  - **에러 처리 테이블**: 에러 유형 | 발생 조건 | 처리 방법 | 사용자 메시지 형식의 테이블.
  - **엣지 케이스**: 경계값, 동시성 문제, 빈 입력 등 고려해야 할 특이 케이스를 나열한다.

### 3. 프로토콜 설계 (해당하는 경우)
- 시스템 간 통신이 있다면:
  - **메시지 포맷**: JSON 스키마 또는 프로토콜 버퍼 형태로 메시지 구조를 정의한다.
  - **핸드셰이크 시퀀스 다이어그램**: 연결 수립 과정을 시퀀스 다이어그램(ASCII 또는 Mermaid)으로 표현한다.
  - **상태 전이**: 연결 상태 변화를 상태 다이어그램으로 표현한다.
- 통신 프로토콜이 불필요한 프로젝트라면, API 엔드포인트 설계 또는 모듈 간 인터페이스 설계로 대체한다.

### 4. 보안 고려사항
- **암호화 계층**: 데이터 전송 및 저장 시 적용할 암호화 방식을 명시한다.
- **위협 모델**: 주요 위협 시나리오와 대응 방안을 테이블로 정리한다 (위협 | 영향도 | 대응 방안).
- **알려진 제한**: 현재 설계에서 완전히 해결하지 못하는 보안 이슈를 투명하게 기술한다.
- **인증/인가**: 사용자 인증 방식, 권한 관리 체계를 설명한다 (해당하는 경우).

### 5. 개발 일정 및 마일스톤
- Phase별로 다음을 정의한다:
  - **목표**: 해당 Phase에서 달성할 핵심 목표
  - **주요 작업**: 구체적인 개발 태스크 목록
  - **산출물**: Phase 완료 시 기대하는 결과물
- 전체 Phase를 3~5단계로 나누어 점진적 개발 계획을 수립한다.

### 6. 디렉토리 구조
- 프로젝트의 최종 디렉토리 구조를 **트리 형태**로 표현한다.
- 각 주요 디렉토리와 파일의 역할을 간략히 주석으로 설명한다.

## 작성 원칙

- **언어**: 한글로 작성한다.
- **톤**: 기술 문서 톤을 유지한다. 이모지를 사용하지 않는다.
- **일관성**: PRD1.md에서 정의한 용어, 기능명, 기술스택을 그대로 사용한다.
- **구체성**: 개발자가 이 문서만 보고 구현에 착수할 수 있을 수준으로 상세하게 작성한다.
- **범용성**: 특정 프로젝트 유형에 종속되지 않도록 범용적으로 작성한다.
- **실용성**: 이론적 완벽함보다 실제 구현 가능한 현실적 설계를 지향한다.
