# /rw:prd:prd1 — 러프 기획 문서(PRD1) 생성

사용자가 `$ARGUMENTS`로 전달한 프로젝트 설명을 바탕으로, 프로젝트 루트에 **PRD1.md** 파일을 생성한다.

## 실행 절차

1. 먼저 코드베이스를 탐색하여 이미 존재하는 코드, 설정 파일, README 등을 파악한다.
2. `$ARGUMENTS`와 코드베이스 분석 결과를 종합하여 PRD1.md를 작성한다.
3. 프로젝트 루트에 `PRD1.md` 파일을 Write 도구로 생성한다.

## PRD1.md 문서 구조

아래 섹션을 **반드시 모두 포함**하여 한글로 작성한다.

### 1. Context
- 프로젝트의 배경, 동기, 해결하려는 문제를 서술한다.
- 목표 사용자(타깃)와 핵심 가치를 명확히 정의한다.

### 2. 러프한 기능 정리
- **핵심 기능 테이블**: 기능명 | 설명 | 우선순위(P0/P1/P2) 형식의 마크다운 테이블로 정리한다.
- **부가 기능**: 핵심 기능 이외에 고려할 수 있는 부가 기능을 간략히 나열한다.

### 3. 기술스택 선정
- **아키텍처 개요 다이어그램**: ASCII 또는 Mermaid 형식으로 시스템 전체 구조를 도식화한다.
- **기술 결정 테이블**: 영역(프론트엔드, 백엔드, DB 등) | 기술 | 대안 | 선정 근거 형식의 테이블을 작성한다.
- **선정 근거**: 각 기술 선택의 이유를 구체적으로 설명한다 (성능, 생태계, 학습 곡선 등).

### 4. 대단위 기능 정의
- 핵심 기능 각각에 대해 다음을 기술한다:
  - **개요**: 기능이 무엇인지 한두 문장으로 요약
  - **동작 방식**: 사용자 관점에서의 주요 흐름 설명
  - **제약사항/고려사항**: 성능, 보안, 호환성 등 알려진 제약

### 5. 주요 의존성 패키지
- 패키지명 | 용도 | 버전(권장) 형식의 테이블로 정리한다.
- 핵심 런타임 의존성과 개발 의존성을 구분하여 나열한다.

### 6. 다음 단계
- PRD 2단계(PRD2.md)에서 다룰 내용을 예고한다.
- 상세 설계, 와이어프레임, 프로토콜 설계, 보안 고려사항, 개발 일정 등이 포함될 것임을 명시한다.

## 작성 원칙

- **언어**: 한글로 작성한다.
- **톤**: 기술 문서 톤을 유지한다. 이모지를 사용하지 않는다.
- **분량**: 각 섹션을 충실히 채우되, 불필요한 반복은 피한다.
- **범용성**: 특정 프로젝트 유형에 종속되지 않도록 범용적으로 작성한다.
- **실행 가능성**: 이 문서를 읽고 개발팀이 바로 기술 검토에 들어갈 수 있을 수준으로 작성한다.
