# /rw:plan:plan — 작업 계획(plan.md) 생성

argument를 기반으로 작업 계획을 수립하여 프로젝트 루트에 plan.md를 생성한다.

## 1단계: 사전 검증

1. `$ARGUMENTS`가 비어있으면 프로젝트 루트에 `spec.md`가 있는지 확인한다.
   - 있으면 `spec.md`를 입력으로 삼고, 어떤 파일을 사용하는지 사용자에게 알린 뒤 진행한다:
     > argument가 없어 프로젝트 루트의 spec.md를 입력으로 사용합니다.
   - 없으면 다음 메시지를 출력하고 **중단**한다:
     > argument가 비어 있고 프로젝트 루트에 spec.md도 없습니다. 구현할 기능 설명 텍스트 또는 spec/PRD 파일 경로를 입력해 주세요.
     > 예: `/rw:plan:plan PRD2.md` 또는 `/rw:plan:plan 사용자 인증 기능 구현`
     > 기능 명세부터 만들려면 `/rw:spec:spec 사용자 인증 기능`을 먼저 실행해 주세요.

2. 프로젝트 루트에 `plan.md`가 이미 존재하는지 확인한다. 존재하면 다음 메시지를 출력하고 **중단**한다:
   > 프로젝트 루트에 plan.md가 이미 존재합니다.
   > `/rw:plan:plan_move`를 실행하여 기존 plan.md를 아카이빙한 후 다시 `/rw:plan:plan` 명령을 실행해 주세요.

## 2단계: argument 해석

- `$ARGUMENTS`가 `.md`, `.txt` 등 파일 확장자를 포함하는 경로이면 해당 파일을 Read 도구로 읽어 내용을 파악한다. 파일이 존재하지 않으면 사용자에게 알리고 중단한다.
- 파일 경로가 아닌 일반 텍스트이면 해당 텍스트를 직접 분석한다.
- 1단계에서 루트 `spec.md`를 입력으로 정한 경우도 같은 방식으로 Read하여 파악한다.

## 3단계: 코드베이스 탐색

argument 내용을 파악한 뒤, 관련된 코드베이스를 탐색하여 현재 구현 상태, 디렉토리 구조, 기존 패턴 등을 파악한다.

## 4단계: plan.md 생성

**Write 직전에 루트 `plan.md`의 존재 여부를 다시 확인한다.** 1단계 검사와 이 시점 사이에는 코드베이스 탐색이 끼어 있어 수 분이 걸리며, 그동안 다른 세션이 `plan.md`를 만들었을 수 있다. 그 사이 생겼으면 덮어쓰지 말고 다음을 출력한 뒤 **중단**한다:

> 계획을 세우는 동안 프로젝트 루트에 plan.md가 새로 생겼습니다. 다른 세션이 만들었을 수 있어 덮어쓰지 않고 중단합니다. 내용을 확인한 뒤 필요하면 `/rw:plan:plan_move`로 아카이빙하고 다시 실행해 주세요.

확인이 끝나면 argument 내용 + 코드베이스 분석 결과를 종합하여 프로젝트 루트에 `plan.md`를 Write 도구로 생성한다.

### plan.md 문서 구조

```markdown
# 기능 개요

(argument 내용을 정리한 기능 설명. 무엇을 왜 만드는지 대략적으로 서술한다.)

## 구현 목표

(달성해야 할 핵심 목표를 명확히 정의한다.)

- 목표 1
- 목표 2
- ...

## 설계

(구현에 필요한 핵심 설계 사항을 정리한다. 변경/생성할 주요 클래스, 계층 구조, 데이터 흐름 등을 포함한다.)

## 작업 계획

### Phase 1: (단계 이름)

- [ ] 테스트 항목 1
- [ ] 테스트 항목 2

### Phase 2: (단계 이름)

- [ ] 테스트 항목 3
- [ ] 테스트 항목 4

(필요한 만큼 Phase를 추가한다)
```

### 작성 원칙

- 체크리스트 항목은 **테스트 단위**로 작성한다. `/rw:tdd:go`가 이 목록에서 미완료 테스트를 하나씩 찾아 Red-Green으로 구현하는 전제이므로, 각 항목은 하나의 실패 테스트로 표현 가능해야 한다.
- 체크박스 상태는 세 가지다: `- [ ]` 미완료, `- [~]` 진행 중(어떤 세션이 선점함), `- [x]` 완료. **생성 시점에는 모든 항목을 `- [ ]`로 쓴다.** `[~]`는 `/rw:tdd:go`가 실행 중에만 찍고 완료 시 `[x]`로 바꾸는 표시이므로, 계획을 세우면서 미리 넣지 않는다.
- 항목은 하나의 논리적 작업 단위로 쪼갠다. 한 항목이 너무 크면 세분화한다.
- 각 항목은 구체적이어야 한다. "구현한다"가 아니라 어떤 동작을 어떻게 검증하는지 명시한다.
- Phase는 의존성 순서에 따라 배치한다. 선행 작업이 먼저 온다.
- 프로젝트의 .claude/rules/ 에 정의된 규칙(계층 분리, DDD, Service/Finder 분리 등)을 준수하는 설계를 반영한다.
- 입력이 `spec.md`이면 "완료의 정의" 항목이 테스트 체크리스트로 빠짐없이 반영되었는지 확인한다. "미해결 질문"이 남아 있으면 임의로 결정하지 말고 결과 보고에서 사용자에게 알린다.

## 결과 보고

- 생성된 파일 경로(`plan.md`)
- 기능 개요 요약(1~2문장)
- Phase 수와 테스트 항목 수
- 입력이 `spec.md`이고 "미해결 질문"이 남아 있었다면 그 목록

## 하지 말아야 할 것

- argument가 비어 있고 루트에 spec.md도 없는데 임의로 진행하기 (사전 검증에서 반드시 중단)
- spec.md의 미해결 질문을 임의로 결정해서 계획에 반영하기 (결과 보고에서 사용자에게 알린다)
- 프로젝트 루트에 plan.md가 이미 존재하는데 덮어쓰기 (`/rw:plan:plan_move`로 먼저 아카이빙 안내)
- 1단계 검사만 믿고 Write 직전 재확인을 건너뛰기 (탐색 중 다른 세션이 만든 plan.md를 덮어쓰게 된다)
- 존재하지 않는 파일 경로를 임의로 무시하고 진행하기
- 프로젝트의 .claude/rules/ 규칙(계층 분리, DDD, Service/Finder 분리 등)을 무시한 설계를 반영하기
