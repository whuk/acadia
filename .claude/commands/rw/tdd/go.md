# /rw:tdd:go — 다음 미완료 테스트 TDD 구현

plan.md에서 다음 미완료 테스트(체크 표시가 없는 테스트) 하나를 찾아 TDD 사이클(Red-Green)로 구현합니다. CLAUDE.md의 TDD 사이클(Red-Green-Refactor) 중 Refactor 단계는 이 커맨드의 범위 밖입니다 — 필요하면 Green 확인 후 별도 작업으로 수행합니다.

## 1단계: 대상 테스트 선정 및 선점 표시

plan.md는 여러 세션(다른 터미널, worktree, 병렬 에이전트)이 동시에 읽고 쓸 수 있습니다. 선점 표시 없이 진행하면 두 세션이 같은 테스트를 중복 구현합니다.

1. plan.md를 읽고 **`- [ ]`(미완료)인 항목 중 첫 번째** 하나를 찾으세요. `- [x]`(완료)와 `- [~]`(다른 세션이 진행 중)는 건너뜁니다.
2. 대상이 없으면(모두 `[x]`이거나 남은 것이 전부 `[~]`) 그 사실을 알리고 **중단**하세요. `[~]`만 남았다면 다른 세션이 작업 중일 수 있다는 점을 함께 알립니다.
3. **선정 즉시** 그 줄만 Edit로 `- [~]`로 바꿔 선점을 표시하세요. 파일 전체를 Write로 다시 쓰지 마세요 — 다른 세션이 같은 시각에 찍은 체크가 사라집니다.
   ```
   - [ ] 잔액이 부족하면 주문 생성이 거부된다
   → - [~] 잔액이 부족하면 주문 생성이 거부된다
   ```
4. 이 표시를 마친 뒤에만 2단계로 진행합니다. 해당 테스트 하나만 구현 대상으로 삼으세요.

## 2단계: Red — 실패 확인

해당 테스트를 작성하고, 실행하여 실패를 확인하세요.

## 3단계: Green — 최소 구현

1. 테스트를 통과시키기 위한 최소한의 코드를 구현하세요.
2. 모든 테스트를 실행하여 통과를 확인하세요.

## 4단계: plan.md 체크

1. plan.md를 **다시 읽으세요.** 1단계 이후 다른 세션이 같은 파일의 다른 항목을 갱신했을 수 있습니다.
2. 1단계에서 `[~]`로 표시한 그 줄만 Edit로 `- [x]`로 바꾸세요. **파일 전체를 Write로 다시 쓰지 마세요** — 그 사이 다른 세션이 찍은 체크를 덮어쓰게 됩니다.
3. 다시 읽은 plan.md에서 그 줄이 사라졌거나 이미 `- [x]`이면 덮어쓰지 말고, 구현 결과와 함께 그 사실을 결과 보고에 남기세요(중복 구현이 발생했을 수 있습니다).

## 5단계: 중단 시 선점 해제

2~3단계에서 구현을 완료하지 못하고 중단하는 경우(테스트를 통과시키지 못했거나 사용자가 중지), 1단계에서 찍은 `- [~]`를 `- [ ]`로 되돌린 뒤 종료하세요. 되돌리지 않으면 그 항목이 다음 실행에서 영영 선택되지 않습니다.

## 결과 보고

- 구현한 테스트가 무엇인지
- 테스트 실행 결과 (Red 확인 → Green 통과)
- 4단계 3항에 해당했다면(다른 세션이 같은 항목을 먼저 완료) 그 사실
- 중단한 경우 선점 표시를 되돌렸는지

## 하지 말아야 할 것

- 여러 테스트를 한꺼번에 구현하기
- 테스트 통과에 필요한 것 이상의 코드를 추가하기
- 이 단계에서 리팩터링하기
- 실패 테스트 검증을 건너뛰기
- 선점 표시(`- [~]`) 없이 곧바로 구현에 들어가기 (다른 세션과 중복 구현이 발생한다)
- plan.md를 파일 전체 Write로 갱신하기 (해당 줄만 Edit — 동시 갱신분이 사라진다)
- 중단하면서 `- [~]`를 되돌리지 않고 종료하기
