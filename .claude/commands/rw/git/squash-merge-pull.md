# /rw:git:squash-merge-pull — PR squash merge 및 main 동기화

GitHub PR을 squash merge하고 로컬 main 브랜치를 최신 상태로 동기화합니다.

## 1단계: 대상 PR 결정

다음 순서로 분기 판정하세요.

### 경로 A: `$ARGUMENTS`에 PR 번호가 입력된 경우

`#123`, `123` 형식에서 숫자만 추출해 대상 PR로 삼습니다.

### 경로 B: `$ARGUMENTS`가 비어 있는 경우

1. `gh pr list --head <현재 브랜치> --state open --json number,url,title,baseRefName`으로 **현재 브랜치의** 열린 PR을 조회합니다. 저장소에서 가장 최근에 열린 PR을 집지 마세요 — 지금 작업 중인 브랜치와 무관한 PR을 머지할 수 있습니다. `gh pr view`(인자 없음)는 후보가 여럿이어도 하나만 반환하므로 3항의 확인 절차를 지원하지 못합니다.
2. 현재 브랜치에 열린 PR이 없으면 다음 메시지를 출력하고 **중단**하세요:
   > 현재 브랜치에 열린 PR이 없습니다. 머지할 PR 번호를 인자로 넘기거나(`/rw:git:squash-merge-pull 123`), PR을 먼저 생성해 주세요.
3. 여러 PR이 후보로 잡히면 목록을 보여주고 사용자에게 대상을 확인받습니다. 임의로 고르지 마세요.

## 2단계: PR 상태 확인

- `gh pr view <PR번호> --json title,state,mergeable,headRefName,baseRefName`으로 PR 정보를 조회합니다
- PR이 이미 머지되었거나 닫혀 있으면 사용자에게 알리고 중단합니다
- merge 가능 여부(mergeable)를 확인하고, 충돌이 있으면 사용자에게 알리고 중단합니다

## 3단계: 로컬 작업 디렉토리 확인 (머지 전)

머지는 되돌릴 수 없고 원격 브랜치까지 삭제하므로, 머지 이후 단계를 막을 수 있는 조건은 **머지 전에** 모두 확인합니다.

- `git status --short`로 커밋되지 않은 변경사항이 있는지 확인합니다.
- 변경사항이 있으면 사용자에게 알리고 다음 중 하나를 확인받습니다. 확인 없이 4단계로 진행하지 않습니다:
  - `git stash push -u`로 잠시 치워두고 진행한다 (6단계 동기화 후 7단계에서 복원)
  - 여기서 **중단**하고 사용자가 직접 커밋·정리한 뒤 다시 실행한다
- stash를 선택했으면 그 사실과 복원 시점을 4단계 확인 화면에 함께 표시합니다.

## 4단계: 머지 전 사용자 확인

- PR 제목, 번호, 소스 브랜치 → 타겟 브랜치 정보를 표시합니다
- 3단계에서 stash를 선택했으면 그 사실을 함께 표시합니다
- 위 정보를 보여주고 머지 진행 여부를 확인받습니다. 확인 없이 5단계로 진행하지 않습니다

## 5단계: squash merge 수행

- `gh pr merge <PR번호> --squash --delete-branch`를 실행합니다

## 6단계: 로컬 기본 브랜치 동기화

- **remote 이름을 `origin`으로 가정하지 마세요.** 저장소마다 이름이 다르고 여러 개일 수 있습니다. `git remote`로 목록을 보고, 하나뿐이면 그것을, 여러 개면 `git config --get branch.{기본브랜치}.remote`로 기본 브랜치가 추적 중인 remote를 사용합니다. 판정이 안 되면 사용자에게 확인받습니다.
- 기본 브랜치명은 `git remote show {remote}`의 HEAD 브랜치로 확인합니다(`main`이 아닐 수 있습니다).
- `git checkout {기본브랜치} && git pull {remote} {기본브랜치}`를 실행합니다. 작업 디렉토리는 3단계에서 이미 정리했으므로 여기서 다시 검사하지 않습니다

## 7단계: 정리 작업

- 삭제된 리모트 브랜치에 대응하는 로컬 브랜치가 있으면 정리합니다. squash merge는 커밋 그래프상 머지가 아니어서 `git branch -d`가 "not fully merged"로 거부되므로, PR이 실제로 머지된 것을 2·5단계에서 확인한 뒤 `git branch -D <브랜치명>`을 사용합니다
- `git fetch --prune {remote}`로 리모트 추적 브랜치를 정리합니다(6단계에서 확정한 remote 이름을 사용합니다)
- 3단계에서 stash 했다면 `git stash pop`으로 복원합니다. 충돌이 나면 자동으로 해소하지 말고 사용자에게 알립니다

## 결과 보고

- 머지된 PR 정보 (번호, 제목)
- 현재 브랜치와 최신 커밋 정보
- 3단계에서 stash 했다면 복원 결과 (충돌로 복원하지 못했으면 그 사실과 `git stash list` 위치)

## 하지 말아야 할 것

- 사용자 확인 없이 머지를 실행하기
- 인자가 없을 때 현재 브랜치와 무관한 PR(저장소의 가장 최근 열린 PR 등)을 임의로 골라 머지하기 (1단계 경로 B)
- 후보 PR이 여럿인데 확인 없이 하나를 골라 머지하기
- merge 불가능한 PR을 강제로 머지하기
- 되돌릴 수 없는 머지를 실행한 **뒤에** 워킹트리 상태를 확인하기 (3단계에서 머지 전에 확인한다)
- remote 이름을 `origin`으로, 기본 브랜치명을 `main`으로 가정하기 (6단계에서 실제 값을 확정한다)
- 기본 브랜치가 아닌 다른 브랜치에서 pull 수행하기
- 로컬에 커밋되지 않은 변경사항이 있을 때 checkout하기 (3단계에서 stash 또는 중단으로 처리한다)
- stash 해놓고 복원하지 않은 채 종료하기 (7단계에서 복원하고, 실패했으면 결과 보고에 남긴다)
