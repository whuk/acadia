# /rw:spec:spec_move — spec.md 아카이빙

프로젝트 루트의 spec.md 파일을 읽고 내용을 요약한 뒤, 요약 키워드가 포함된 파일명으로 변경하여 specs 디렉토리로 아카이빙한다.

## 1단계: spec.md 읽기

프로젝트 루트의 `spec.md`를 Read 도구로 읽는다. 파일이 존재하지 않으면 사용자에게 알리고 중단한다.

## 2단계: 요약 키워드 생성

파일 내용을 분석하여 핵심 주제를 나타내는 3~5단어의 한글 요약 키워드를 생성한다.

- 요약 키워드는 밑줄(`_`)로 연결한다 (예: `로그인_실패_계정_잠금`)
- 공백, 특수문자, 영문 대문자를 키워드에 포함하지 않는다

## 3단계: 새 파일명 결정

오늘 날짜를 `yyyyMMdd` 형식으로 구하고, 새 파일명을 결정한다: `spec_yyyyMMdd_요약키워드.md`

## 4단계: specs 디렉토리로 이동

파일명이 날짜 + 요약 키워드로만 구성되므로 같은 날 비슷한 주제를 아카이빙하면 이름이 겹친다. `mv`는 대상이 있어도 조용히 덮어쓰므로 **이동 전에 반드시 존재 여부를 확인한다.**

1. 프로젝트 루트에 `specs/` 디렉토리가 존재하는지 확인한다. 없으면 `mkdir -p specs`로 생성한다.
2. 대상 경로가 이미 있는지 확인한다:
   ```bash
   test -e specs/{새파일명}.md && echo EXISTS || echo FREE
   ```
3. `EXISTS`이면 덮어쓰지 말고 사용자에게 기존 파일의 수정일·크기와 함께 알린 뒤 확인받는다. 숫자 접미사(`spec_yyyyMMdd_요약키워드_2.md`, `_3.md`, …)로 비켜 가는 것을 기본 제안으로 제시한다.
4. 충돌이 없는 이름이 확정되면 이동한다. `mv -f`를 쓰지 않는다:
   ```bash
   mv spec.md specs/{최종파일명}.md
   ```

## 결과 보고

- 원본 파일: `spec.md`
- 새 파일명: `spec_yyyyMMdd_요약키워드.md`
- 이동 경로: `specs/spec_yyyyMMdd_요약키워드.md`
- spec.md 내용 요약 (2~3문장)
- 미해결 질문이 남아 있었다면 그 목록 (아카이빙 후에는 확인하기 어려우므로 여기서 알린다)

## 하지 말아야 할 것

- spec.md가 없는데 빈 파일을 생성하기
- 요약 키워드에 공백이나 특수문자 포함하기
- 존재 여부를 확인하지 않고 `mv`를 실행하기 (4단계 2항 — `mv`는 조용히 덮어쓴다)
- 기존 specs 디렉토리 내 동일 파일명이 있을 때 덮어쓰기 (충돌 시 사용자에게 확인 요청)
- `mv -f`로 충돌을 무시하고 밀어붙이기
- spec.md 원본 내용을 수정하기
